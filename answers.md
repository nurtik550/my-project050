# Ответы на контрольные вопросы

1. **Что такое Merge Conflict?**  
   Это конфликт слияния, который возникает, когда Git не может автоматически объединить изменения в одном и том же участке файла.

2. **Почему в этой практике возник конфликт?**  
   Ветки `main` и `feature-message` были созданы от одной исходной версии, а затем одна и та же строка была изменена в каждой ветке по-разному.

3. **Почему важно создать обе ветки до изменения исходного файла?**  
   Чтобы обе ветки начинались от общей исходной версии и содержали независимые изменения одной строки.

4. **Чем отличаются `git fetch` и `git pull`?**  
   `git fetch` получает сведения и изменения с удалённого репозитория, но не объединяет их с текущей веткой. `git pull` получает изменения и интегрирует их в текущую ветку.

5. **Для чего нужен Pull Request?**  
   Чтобы предложить изменения из одной ветки для включения в другую, проверить их и обсудить перед слиянием.

6. **Почему мы объединили `origin/main` в `feature-message`, а не наоборот?**  
   Чтобы разрешить конфликт в ветке `feature-message`, отправить исправление в GitHub и затем завершить Pull Request в `main`.

7. **Для чего используется окно Resolve Conflicts в PyCharm?**  
   Для сравнения конфликтующих версий файла и ручного выбора или редактирования итогового содержимого.

8. **Что такое итоговая версия файла (Result)?**  
   Это окончательный вариант файла, который останется после разрешения конфликта.

9. **Почему после разрешения конфликта нужно сделать коммит?**  
   Чтобы сохранить разрешённое слияние в истории Git и завершить операцию merge.

10. **Для чего нужна команда `git push` после разрешения конфликта?**  
    Чтобы отправить созданный коммит и обновлённую ветку в удалённый репозиторий GitHub.
